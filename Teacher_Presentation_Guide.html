1. What Is This Project? (The Simple Explanation)

In simple terms, this project is a complete Student Attendance Management System where teachers can register students, mark daily attendance (Present/Absent), and search attendance history.

However, the real core of this project is the DevOps automation pipeline built around it: Instead of running the application manually, every phase — testing, cloud integration, container packaging, deployment, persistent data storage, and health monitoring — is automated using industry-standard tools.

🗣️ How to Open Your Presentation (30-Second Pitch):
"Good morning Sir/Ma'am. My DevOps project is a Student Attendance Management System. Rather than simply running code locally, I built an end-to-end DevOps pipeline: The Flask and SQLite application is automatically tested using Pytest, continuously integrated on GitHub Actions on every push, packaged into a secure non-root Docker container, deployed to Kubernetes with persistent storage, and monitored in real-time with Prometheus and Grafana."

3. Cloud CI Pipeline (FA1)

Dockerfile packages the app into student-attendance:v1 running as unprivileged appuser with built-in health checks.

Prometheus periodically scrapes /metrics every 10s; Grafana provides real-time visual dashboards for latency and request rates.

5. Top 5 Viva Questions & Answers

Q1: Why is the replica count strictly 1 in your Kubernetes deployment?

Answer: SQLite is an embedded single-file database that uses file-level locks. If multiple pods write to the same SQLite file simultaneously over network storage, file locking fails, causing "database is locked" errors or corruption. That is why we use 1 replica with ReadWriteOnce storage and a Recreate strategy. In production, for horizontal scaling (replicas > 1), we would migrate to PostgreSQL or MySQL.

Q2: What is the difference between a Container and a Virtual Machine?

Answer: A Virtual Machine contains a full Guest Operating System running on top of a hypervisor, making it heavy and slow to boot. A Docker container shares the host OS kernel and packages only the application and its dependencies, making it lightweight, fast to start, and portable.

Q3: What are Liveness and Readiness probes in Kubernetes?

Answer: A Readiness probe checks if the container is ready to accept incoming user traffic (if it fails, Kubernetes stops sending traffic to it). A Liveness probe checks if the container has frozen, deadlocked, or crashed (if it fails, Kubernetes automatically restarts the pod).

Q4: Why does your Dockerfile run as an unprivileged user (appuser)?

Answer: This adheres to the Principle of Least Privilege for container security. If an attacker breaches the application, they cannot gain root privileges on the underlying host operating system.

Q5: What is the difference between a Counter and a Gauge in Prometheus?

Answer: A Counter is a metric that can only increase or reset to zero (e.g., total HTTP requests). A Gauge is a metric that can go both up and down to reflect the current value (e.g., total number of registered students).
